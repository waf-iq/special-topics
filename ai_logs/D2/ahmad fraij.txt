## 7) Key Technical Decisions and Tradeoffs

1. **Smoke vs quality assertions**  
   D2 smoke tests verify uptime/connectivity/seed sanity, not ranking quality. This avoids flaky tests and keeps quality evaluation in dedicated metrics tasks.

2. **Direct localhost integration checks**  
   Test targets developer-host mapped ports directly (no heavyweight compose fixture), reducing run overhead and matching actual operational use.

3. **Dev-mode auth assumptions**  
   Neo4j dev setup uses `NEO4J_AUTH=none`; production should move credentials to env and update checks accordingly.

4. **Loose count thresholds**  
   Thresholds are intentionally conservative to detect missing seed runs while avoiding fragility as corpus size evolves.

5. **Per-source Qdrant collection validation**  
   Explicit checks for `chunks_bge384_scifact`/`_arxiv` catch partial reseed failures early and prevent opaque runtime `/search` errors.

- **Eval contamination across sources** -> Mitigated by source-filter path and source-specific checks.
- **Service drift between local/dev environments** -> Mitigated with compose + `.env.example` + healthz + smoke gates.
- **Graph metadata incompleteness** -> Documented as a known limitation and staged for D3 expansion.
